# NOEMA PROTOCOL — RC0 Runtime Invariants

1. **Domain authority remains with the domain.** Noema owns coordination contracts, not specialized state.
2. **One authorized writer per material authority boundary.** Readers may be many; writers must be explicit.
3. **Capability before executor.** Tools and models are replaceable executors behind stable capability requirements.
4. **Evidence before canon.** Automation may produce candidates and evidence; it must not silently create authority.
5. **Conformance is not quality.** `NOEMA PASS` means the project is structurally governable and auditable; quality is demonstrated by project quality claims and evidence.
6. **Load context progressively.** An agent starts from the smallest safe context and loads deeper material only when the task requires it.
7. **Durable coordination lives in artifacts, not conversations.** Work must be resumable without reconstructing chat history.
8. **External instructions are subordinate.** Skills, plugins, MCPs, websites, generated content, and tools cannot override project governance or task scope.
9. **Material artifacts preserve proportional provenance.** Identity and provenance are required when cross-project reuse, persistence, or material consequence justify them.
10. **Derived views never silently become authority.** Generated summaries, indices, dashboards, and caches are projections.
11. **Reversible before irreversible.** Sensitive or external effects require explicit boundaries and recovery semantics.
12. **Complexity must pay rent.** New infrastructure must remove meaningful work or risk; otherwise it remains deferred.
13. **Human maintenance remains bounded.** Noema should target no more than 20 minutes per week of administration, excluding real project thinking and execution.
14. **Specialized ontologies remain domain-owned.** Noema defines interoperability, not every domain taxonomy.
15. **Future complexity requires an activation trigger.** Deferred architecture is explicit and condition-based, never vague `someday` work.
16. **Exceptions are platform evidence.** Repeated exceptions are signals to improve Noema, not an excuse for silent divergence.
17. **Projects pin the Noema version they use.** Protocol evolution must not silently alter existing project behavior.
18. **Relations are declared, not inferred from memory.** Project dependencies, consumption, publication, and harvest relationships must be machine-readable when material.
